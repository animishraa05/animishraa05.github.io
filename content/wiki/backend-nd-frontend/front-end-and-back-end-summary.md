## What Concepts Were Extracted

1. **Front End** — The presentation layer users interact with directly; client-side technologies and UI
2. **Back End** — Data management and processing layer; server-side logic, databases, APIs
3. **Full Stack** — Both front end and back end together; entire application stack
4. **Client-Server Model** — Architecture where client handles UI, server handles data/processing
5. **API** — Interface for front end to communicate with back end, typically over HTTP

## Key Takeaways

- Front end (client side) handles all user-facing components: UI, rendering, input handling
- Back end (server side) handles data storage, business logic, authentication, security
- Full stack combines both, requiring knowledge across the entire application
- API is the bridge between front end and back end using HTTP requests/responses
- The BFF (Backend for Frontend) pattern optimizes APIs for specific front-end interfaces

## Novelty

This source provides a comprehensive overview of the front end/back end distinction across multiple contexts:

- General software architecture (presentation layer vs data management)
- Web development (HTML/CSS/JS vs server languages/databases)
- Content management systems (user views vs admin views)
- Speech synthesis (text to phonetic vs phonetic to sound)
- Compilers (parsing to intermediate vs optimizing to executable)
- Hardware networking (network interface vs data transport)
